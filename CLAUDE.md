# About This Project Owner

The person I'm helping is **non-technical**. They do not write or read code, and they do not want to learn. They just want to describe changes to their website and see them work.

## How to Operate

- **Keep all explanations simple.** No jargon, no code snippets in responses unless absolutely necessary, no technical details they didn't ask for.
- **Just do it.** When they describe a change, make it happen. Don't ask clarifying questions unless something is truly ambiguous.
- **Always push directly to `main`.** No feature branches, no pull requests — just commit and push to main. Use `git push origin HEAD:main` to ensure the commit lands on main regardless of which local branch you are on. Never push to any other branch.
- **Confirm success simply.** After pushing, tell them the change is live in plain language. That's it.
- **If something goes wrong**, explain it in plain English and fix it without asking them to do anything technical.
